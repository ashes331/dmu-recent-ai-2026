## 실행 순서 (수업 진행 순서)

```bash
# ── 수업 전날 (교수) 🔶 ─────────────────────────────────────
python split_compare.py --search   # ★★ 세 결과가 실제로 갈리는지 확인
python embed.py --check            # ★★ 임베딩 모델이 한국어를 잡는지 확인

# ── 1교시 : 적재
python loaders.py                  # 실습 1 (네트워크 없음)
python loaders.py --web            #   Web 까지 (⚠️ 조별 순차)

# ── 2교시 : 분할 ★★ 이 교시가 10주차의 핵심
python split_compare.py            # 1단계 — 어디서 끊겼는지 눈으로 (무료·즉시) ★
python split_compare.py --search   # 2단계 — 같은 질문, 다른 결과 ★★
python split_compare.py --meta     # 3절  — 메타데이터 설계 ★★

# ── 3교시 : 임베딩 + 저장
python embed.py --check            # 한국어 검증 ★★
python embed.py                    # 임베딩 + 인덱스 저장 ★★ 반드시 커밋
```

## ★★ 이 차시의 결정적 장면 — 배포 문서는 '일부러' 이렇게 만들었습니다

`data/학칙.md` 는 **500자 경계가 정답 숫자 바로 앞에 떨어지도록** 길이를 맞춘 문서입니다.

```
   [A 고정 500자]
     청크1 끝 : "... ② 일반휴학은 학기 단위로 신청하며 통산"      ← 여기서 끊긴다 ⚠️
     청크2 앞 : "6개 학기를 초과할 수 없다. ③ 휴학원은 ..."

   질문: "일반휴학은 통산 최대 몇 학기까지 할 수 있나요?"
        │
        ├─ 청크1 은 질문과 매우 비슷하다  →  **검색 1위로 잘 뽑힙니다**
        └─ 그런데 그 안에 **숫자가 없습니다** ★★
             ▼
        검색은 성공했는데 답을 못 만듭니다. 그리고 모델은 그럴듯하게 지어냅니다.
```

> 📌 **이 장면 하나가 2교시 전체의 논거입니다.**
> B(재귀)는 같은 500자인데 문장이 온전하고, C(구조)는 제12조가 통째로 남습니다.
> **바꾼 것은 자르는 방법뿐입니다.**

🔶 **문서를 교체하면 이 효과가 사라질 수 있습니다.** 다른 문서를 쓸 경우
`python split_compare.py` 로 **첫 청크가 어디서 끊기는지 반드시 확인**하십시오.

## ★ 강의안 코드에서 고친 곳 (실제로 돌려 보고 확인)

**① `page_of(i)` 대신 — 없는 값은 키를 넣지 않습니다** ★

```python
# 강의안 (2교시 3-2)
"page": page_of(i),
    → page_of() 가 정의되어 있지 않고, .md 문서에는 애초에 페이지 개념이 없습니다.

# 이 폴더의 코드 (split_compare.py)
    → page 키를 아예 넣지 않습니다.
      ⚠️ 값이 없다고 None 을 넣으면 안 됩니다 — Chroma 등 일부 저장소가
         metadata 의 None 을 거부합니다. 🔶
      11주차 citation.py 는 m.get('page','?') 로 받아 'p.?' 로 표시합니다.
```

> 📌 **수업에서 그대로 써먹을 수 있는 장면입니다.**
> *"페이지 번호는 PDF Loader 라야 붙습니다."*
> → 설계 원칙 ①(**나중에 복원할 수 없는 것을 우선**)의 실물 사례입니다. ★

**② 메타데이터를 '2단 구성' 으로 심습니다**

강의안은 `chunks_b`(재귀 결과)에 메타데이터를 손으로 붙이는 형태입니다.
그러면 **장·조 정보를 알 방법이 없습니다**(재귀 분할은 구조를 모릅니다).

```
   이 폴더의 코드:  C(구조)로 먼저 나눠 장·조를 얻고 → 긴 섹션만 B(재귀)로 다시
                    = 1-4절에서 "실무에서 흔하다" 고 소개한 바로 그 2단 구성 ★
```

**③ `--search` / `--meta` 를 분리**

`split_compare.py` 는 옵션 없이 돌리면 **임베딩 호출 없이 즉시** 끝납니다.
"어디서 끊겼는가" 를 먼저 눈으로 보게 하고, 검색 비교는 그다음입니다. ★

## 기말고사에 나올 만한 지점

- **RAG 파이프라인 6단계** (Load → Split → Embed → Store → Retrieve → Generate) ★
- ★ **파인튜닝과 RAG 의 선택 기준** — 지식 갱신 주기 / 비용 / **출처 추적 가능성**
- 문서 형식별 **파싱 난점** (표 · 머리말 · 페이지 번호 · 스캔본)
- `Document` 의 두 구성요소와 `metadata` 의 용도
- **분할 전략 3종**의 차이와 각각이 적합한 상황 ★
- ★★ **청크 크기와 오버랩의 트레이드오프** — 작을 때/클 때 각각 무엇이 나빠지는가
- ★★ **메타데이터 설계를 분할 단계에서 해야 하는 이유**
- **임베딩 모델 선택 기준** (한국어 지원 · 차원 · 속도 · 로컬 실행) ★
- 임베딩 모델의 **한국어 성능을 검증하는 방법**
- (4주차 연계) 생성 모델과 임베딩 모델을 **함께 올릴 때의 VRAM 계산**

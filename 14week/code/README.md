## ★ 강의안 코드에서 고친 곳 (실제로 돌려 보고 확인)

**① 워커의 반환 메시지를 정리했습니다** ★

강의안의 `make_worker` 는 워커가 만든 메시지(도구 호출 포함)를 **그대로** 상태에 쌓습니다.
그러면 `tool_calls` 와 `ToolMessage` 의 짝이 어긋나 다음 Supervisor 호출에서
**모델이 혼란스러워하거나 오류가 납니다.** 🔶

```python
# 이 폴더의 코드
return {"messages": [AIMessage(content=f"[{name}] {text}", name=name)]}
    → 관리자는 **"누가 무엇을 보고했는지"** 만 보면 됩니다.
      워커 내부의 도구 호출 과정까지 관리자 대화에 섞을 필요가 없습니다. ★
```

> 📌 **이것 자체가 멀티 에이전트의 요점입니다** — 워커는 안에서 알아서 하고,
> 관리자에게는 **결과만** 보고합니다. 사람 조직과 같습니다. ★

**② 라우팅에 종료 조건을 두 겹으로**

```python
if state["next"] == "FINISH" or state["steps"] >= MAX_STEPS:   # ① 단계 상한
    return "FINISH"
return state["next"] if state["next"] in WORKERS else "FINISH"  # ② 엉뚱한 값 방어
config={"recursion_limit": RECURSION_LIMIT}                     # ③ 안전망
```

소형 모델의 Supervisor 는 헤맵니다. **세 겹 다 필요합니다.**

**③ 구조화 출력 실패를 `writer` 로 흡수**

`with_structured_output(Route)` 가 실패하면 `writer` 로 보내 정리시키고 끝냅니다.
**예외 하나로 실습이 멈추지 않게** 하기 위한 것이며 화면에 ⚠️ 로 표시됩니다.

**④ `streaming.py` 가 1교시 그래프를 실제로 import 합니다**

강의안은 `# ... (1교시 supervisor.py 의 graph 재사용)` 이라고 주석으로만 되어 있습니다.
`supervisor.py` 가 `graph` / `INPUTS` / `CONFIG` / `QUESTION` 을 노출하고,
`streaming.py` 가 그것을 가져다 씁니다.

>

| 구조화 출력 | 스키마 | Pydantic | 5주 |
| **Reflection** | **순환** | LangGraph 엣지 | 12주 |
| **ReAct (에이전트)** | **순환 + 도구** | ToolNode | 13주 |
| Tree of Thoughts | **분기·탐색** | LangGraph | 13주 (개념) |
| **Supervisor** | **분기 + 위임** | 멀티 에이전트 | **14주 — 오늘** |

## ⚠️ 이 차시 최대의 위험 지점 — `evaluate()` 시그니처

```
   ① create_examples() 의 인자 형태
        inputs=/outputs= 리스트   vs   examples=[{...}] dict 리스트
   ② 평가자 함수의 시그니처
        (outputs, reference_outputs)   vs   (run, example)
```

**여기서 막히면 2교시 25분 실습이 통째로 멈춥니다.**

| 대비 | 어디에 |
|---|---|
| 전날 확인 스크립트 | `python check_eval_api.py` — 실제로 1회 실행해 확정 ★ |
| 두 형태 자동 시도 | `make_dataset.py` 의 `add_examples()` |
| 구형 평가자 어댑터 | `evaluators.py` 의 `as_legacy()` / `run_evaluate()` |
| import 경로 차이 | `evaluators.py` 의 `_load_evaluate()` |

## ★ 강의안 코드에서 두 군데를 고쳤습니다 (실제로 돌려 보고 확인)

**① `label: str` → `label: Literal["긍정","부정","중립"]`** ★★

```python
# 강의안 (2교시 3-2 / 3교시 1-2)
label: str = Field(description="긍정/부정/중립 중 하나만")
    → gemma3:4b 가 실제로  label='mixed_sentiment'  를 내놓습니다. ⚠️
      세 라벨이 아닌 값이 나오면 exact_match 가 전부 오답 처리되어
      A/B 비교 자체가 성립하지 않습니다.

# 이 폴더의 코드
label: Literal["긍정", "부정", "중립"] = Field(description="세 가지 중 하나")
    → 스키마에 enum 이 박혀 세 값 외에는 나올 수 없습니다.
```

> 📌 **수업에서 그대로 써먹을 수 있는 장면입니다.**
> `description` 은 **부탁**이고 `Literal` 은 **계약**입니다 —
> 5주차 *"'JSON으로 답해줘' vs `with_structured_output()`"* 과 정확히 같은 구분이고,
> 3교시 3-2 대비쌍 표에 그대로 들어가는 내용입니다. ★

**② `create_examples()` 는 `examples=[{...}]` 형태를 먼저 시도합니다**

`langsmith 0.4.37` 기준으로 강의안의 `inputs=`/`outputs=` 는 **레거시**입니다
(0.3.11부터 `examples=` 로 바뀌었고, 옛 형태는 `**kwargs` 로만 아직 받아 줍니다).
`make_dataset.py` 는 **현재 형태를 먼저** 쓰고 실패하면 레거시로 재시도합니다.

> 확인된 환경: `langsmith 0.4.37` · `langchain 1.0.5` · `langchain-core 1.0.4` ·
> `langchain-ollama 1.0.0` · `python 3.13`.
> ⚠️ **실습실 PC 버전이 다를 수 있습니다.** `python check_eval_api.py` 로 다시 확인하십시오.

## 주의

- 모든 파일 상단에 `MODEL = "gemma3:4b"` 상수를 두었습니다.
  실습실 모델이 다르면 **이 한 줄만** 고치면 됩니다.
- `load_dotenv()` 는 **반드시 파일 맨 위**에 둡니다 (그래서 `import` 순서가 관례와 다릅니다 — 의도된 것입니다).
- `MAX_CONCURRENCY = 1` 로 두었습니다. ⚠️ 8GB VRAM 실습실 보호. 여유가 있으면 2로.
- **평가자는 `exact_match` 하나만** 씁니다. 오늘 과제가 '분류' 이기 때문입니다.
  판정자는 "이런 게 있고 이런 위험이 있다" 를 보기 위해 `llm_judge.py` 에서만 돌립니다. ★
- `examples.py` 의 **라벨링 기준(`LABELING_RULE`)** 을 반드시 함께 읽히십시오.
  기준 없이 라벨을 달면 데이터셋이 흔들리고 그 위의 모든 측정이 무의미해집니다.
